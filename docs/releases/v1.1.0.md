# Multi-Model AI Orchestrator v1.1.0

Optional GitHub Issue automation plus local reliability modules on top of v1.0.0. Stops at ready-for-human-merge. Not published until review.

## GitHub automation

- Issue-driven assisted flow behind `.github/ai-orchestrator.yml` (default off / manual)
- Trusted-actor `ai-auto` gate, labels, Issue form, and self-hosted `ai-issue.yml` workflow
- Canonical state machine with crash recovery / `github resume`
- Idempotent AI-branch push (skip when remote SHA already matches; no force-push; never push `main`)
- GitHub CI watch, bounded fix loop (max 5 attempts), then human review
- Dry-run lifecycle simulator (`github simulate --fixture`)
- Structured automation event logging and `github doctor` diagnostics
- CLI: `github issue run|inspect`, `labels setup`, `status`, `resume`, `authorize`, `simulate`, `doctor`
- Human merge boundary: **no auto-merge**, **no auto-publish**

## Local reliability and orchestration

- Structured `result.json` / run results and local run history (`runs`)
- Repository-scoped notes (`memory`) and a local foreground job queue (`queue`)
- Execution-informed route recommendations (`routing`; opt-in learned path)
- Process / time budgets, captured-output limits, and worker environment filtering
- Stronger worktree / worker isolation and commit-SHA checkpoints
- Windows path and runner reliability (including short-path / worktree identity)

## Limitations

- Queue is local and sequential (no daemon, no distributed scheduler)
- Memory is structured local notes (not vector / semantic search)
- `costUsd` is not implemented and remains unknown / unavailable
- No parallel GitHub Issue processing
- No auto-merge, no auto-publish, no cloud orchestrator
- Worktree isolation and env filtering are not an OS container sandbox

## Unchanged from v1.0

`/ai` and `/ai-team` skills, smart model routing, TEAM loop, `--task-file` transport, global `ai-orchestrator` CLI, and Windows-first spawning.
