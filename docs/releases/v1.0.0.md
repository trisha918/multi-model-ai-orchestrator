# Multi-Model AI Orchestrator v1.0.0

Released from tag `v1.0.0`.

## Highlights

- Smart worker routing among Cursor Agent, Codex, and Gemini/Antigravity
- Smart model routing with capability profiles (`fast`, `balanced`, `strong`, `max`)
- Manual model overrides that never silently fall back
- Cursor, Codex, and Gemini support on a local Windows CLI
- TEAM workflow with per-stage models
- Independent project test runner (exit code, not agent claims)
- Git worktree isolation and source-workspace protection
- Portable Windows installer (`install.ps1`) with user PATH persistence
- Global `ai-orchestrator` command
- Cursor skills that call the global CLI, never a clone path
- Lossless task transport via UTF-8 `--task-file` inbox files
- Model discovery and cache (`ai-orchestrator models`)
- `/ai-models` skill for the current registry

## Smart Routing

| Command | Behavior |
| --- | --- |
| `/ai` | Auto worker + auto model |
| `/ai-codex` | Codex + smart model |
| `/ai-codex-sol` | Codex + manual Sol alias (current verified Sol-family id) |
| `/ai-gemini` | Gemini + smart model |
| `/ai-gemini-pro-high` | Gemini + manual Pro High alias |
| `/ai-team` | Model-aware TEAM |

Automatic selection may fall back to another available capability tier and logs Preferred / Resolved / Reason. Manual selection fails if the requested model is unavailable. Exact resolved ids are always displayed and written to the run log.

## Model-aware TEAM

Cursor planning  
→ Codex implementation  
→ independent tests  
→ Gemini review  
→ bounded Codex fix loop  

Every stage is pinned to the same verified isolated worktree for that run.

## Safety

- Isolated Git worktrees under `%LOCALAPPDATA%\MultiModelAIOrchestrator\worktrees\`
- Main workspace protection (dirty source refused; unexpected source changes are a safety failure)
- No automatic `git reset` / `clean` of user files
- Independent tests after implementation and each fix round
- Workspace identity verification before workers run
- Lossless task transport (`--task-file`, UTF-8 without BOM)
- Gemini/Antigravity sandbox plus before/after git change detection

## Installation

```powershell
git clone https://github.com/trisha918/multi-model-ai-orchestrator.git
cd multi-model-ai-orchestrator
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

Then:

```powershell
ai-orchestrator doctor
```

## Usage examples

```text
/ai Fix the login bug and add tests
/ai-codex Implement an API endpoint
/ai-codex-sol Debug this difficult concurrency issue
/ai-gemini Review the architecture
/ai-gemini-pro-high Perform a deep security review
/ai-team Refactor authentication safely
/ai-models
```

CLI equivalents use `ai-orchestrator run` with `--mode`, `--model`, and `--task-file`.

## Validated Platform

Windows. macOS and Linux are not claimed as supported hosts.

## Tests

At v1.0.0 release time, **105 automated Node tests** passed locally.

GitHub Actions CI on `main` runs `npm ci`, `node --check`, and `npm test` on Windows. It does **not** run live Cursor, Codex, Gemini, or Antigravity workers and does not require those credentials.

## Known limitations

- Windows validated only
- Gemini headless review may still require `--dangerously-skip-permissions` (mitigated by sandbox, isolated worktree, read-only prompt, and git change detection)
- No automatic GitHub PR creation yet
- No automatic deployment
- No self-updater yet (`git pull` + `.\install.ps1`)
- Model availability depends on the installed CLIs and the signed-in account
