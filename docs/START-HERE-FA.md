# از اینجا شروع کنید

این برنامه یک هماهنگ‌کننده است: درخواست شما را به ابزار هوش مصنوعی نصب‌شده روی کامپیوتر می‌دهد، تست‌های پروژه را اجرا می‌کند و نتیجه را نگه می‌دارد. برای استفادهٔ معمولی به GitHub Actions، سرور یا اتومیشن نیاز ندارید.

این راهنما مربوط به شاخهٔ توسعهٔ `codex/reliable-local-and-optional-automation` است. تا زمانی که تغییرات ادغام نشده‌اند، دریافت شاخهٔ `main` امکانات جدید این راهنما را نصب نمی‌کند. میزبان آزموده‌شده Windows است.

## ۱. چه روشی مناسب شماست؟

| نیاز شما | روش | پیش‌نیاز اضافه |
| --- | --- | --- |
| خودم هر بار دستور بدهم | `run` در PowerShell | فقط ابزار انتخابی |
| در چت Cursor دستور بدهم | `/ai-codex`، `/ai-cursor`، `/ai-team` | Cursor و Skillهای پروژه |
| نتیجهٔ اجراهای قبلی را ببینم | `runs` | هیچ |
| نکته‌ای برای پروژه ذخیره کنم | `memory` | هیچ؛ استفاده از یادداشت‌ها اختیاری است |
| چند کار را بعداً به‌ترتیب اجرا کنم | `queue` | هیچ؛ خودتان زمان اجرا را تعیین می‌کنید |
| انتخاب ابزار از نتایج گذشته کمک بگیرد | `routing` | تاریخچهٔ کافی از همین پروژه |
| از Issue تا PR پیش برود | `github` | تنظیم جداگانهٔ GitHub و runner |

اگر تازه شروع کرده‌اید، ابتدا فقط روش اول را انجام دهید. نصب همهٔ مدل‌ها لازم نیست. `TEAM` به هر سه ابزار نیاز دارد.

## ۲. نصب پیش‌نیازها

از منوی Start ویندوز، **PowerShell** را باز کنید. دستورهای داخل کادرها را هر بار یک خط کپی کنید و Enter بزنید. متن‌هایی مانند `C:\Projects\MyApp` نمونه‌اند؛ باید مسیر پروژهٔ خودتان را جایگزین کنید.

۱. [Git for Windows](https://git-scm.com/install/windows) را نصب کنید. Git نسخه‌های فایل‌های پروژه را نگه می‌دارد.

۲. از [سایت Node.js](https://nodejs.org/en/download)، نصب‌کنندهٔ Windows نسخهٔ LTS را بگیرید. پروژه حداقل Node 20 می‌خواهد؛ از نسخهٔ LTS پشتیبانی‌شده استفاده کنید. npm همراه Node نصب می‌شود.

۳. PowerShell را ببندید و دوباره باز کنید، سپس بررسی کنید:

```powershell
git --version
node --version
npm.cmd --version
```

هر دستور باید شمارهٔ نسخه نشان بدهد. پیام «شناخته نشد» یعنی نصب یا PATH کامل نشده است؛ ابتدا همین مشکل را حل کنید.

۴. ابزار هوش مصنوعی دلخواه را جدا نصب و وارد حسابش شوید:

| ابزار | راه نصب و ورود | بررسی |
| --- | --- | --- |
| Codex | [راهنمای رسمی Codex CLI](https://learn.chatgpt.com/docs/codex/cli)، در بخش نصب زبانهٔ Windows را انتخاب کنید؛ سپس `codex` را اجرا کنید و وارد حساب شوید | `codex --version` |
| Cursor Agent | [راهنمای رسمی Cursor CLI](https://prod.cursor.com/help/integrations/cli)، دستور Windows PowerShell را اجرا کنید؛ سپس `agent auth` | `agent --version` |
| Gemini/Antigravity | این پروژه به ابزار `agy` سازگار با قرارداد فعلی خود نیاز دارد؛ نصب برنامهٔ گرافیکی Gemini به‌تنهایی کافی نیست | `agy models` |

برای `agy` این مخزن نصب‌کنندهٔ عمومی فراهم نمی‌کند. اگر آن را ندارید، فعلاً با `--mode codex` یا `--mode cursor` کار کنید؛ `gemini` و `team` را پس از نصب و تأیید سازگاری فعال کنید. نام ابزار انتخابی در `doctor` دیده می‌شود. اشتراک و دسترسی مدل‌ها را خود سرویس ارائه‌دهنده مدیریت می‌کند.

## ۳. نصب خود هماهنگ‌کننده

پوشه‌ای برای ابزارهای خود انتخاب کنید، سپس:

```powershell
git clone --branch codex/reliable-local-and-optional-automation https://github.com/trisha918/multi-model-ai-orchestrator.git
cd multi-model-ai-orchestrator
.\install.ps1
```

اگر ویندوز اجرای همین اسکریپت را مسدود کرد:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

نصب‌کننده دستور سراسری `ai-orchestrator` و Skillهای Cursor را نصب می‌کند و در صورت نیاز مسیر npm را به PATH **کاربر فعلی** اضافه می‌کند. خودش Git، Node یا ابزارهای هوش مصنوعی را نصب نمی‌کند. بعد از نصب، PowerShell و Cursor را دوباره باز کنید.

```powershell
ai-orchestrator version
ai-orchestrator doctor
ai-orchestrator models refresh
```

اگر فقط Codex را نصب کرده‌اید، گزارش نبودن Cursor یا Antigravity طبیعی است؛ برای اجرا صریحاً `--mode codex` بدهید. نبودن تنظیمات GitHub برای کار محلی مانع نیست. دستور `models refresh` فهرست ابزارهای نصب‌شده را تازه می‌کند؛ یک وظیفهٔ کدنویسی اجرا نمی‌کند.

## ۴. آماده‌کردن پروژهٔ خودتان

پوشهٔ ابزار با پوشهٔ پروژه‌ای که می‌خواهید تغییر بدهید فرق دارد. وارد **پروژهٔ هدف** شوید:

```powershell
cd "C:\Projects\MyApp"
git status
```

اگر پروژه از قبل Git دارد، باید دست‌کم یک commit داشته باشد و قبل از اجرای ایزوله، تغییر ثبت‌نشده نداشته باشد. تغییرهای خودتان را بررسی و commit یا stash کنید؛ برنامه چیزی را برای شما پاک نمی‌کند.

اگر پوشه واقعاً پروژهٔ جدیدی است و Git ندارد، ابتدا `.gitignore` مناسبش را بسازید تا فایل‌های خصوصی مانند `.env` و پوشهٔ وابستگی‌ها وارد Git نشوند. سپس:

```powershell
git init
git add .
git diff --cached --stat
git commit -m "Initial project"
```

اگر Git نام و ایمیل می‌خواهد، مقادیر خودتان را برای همین مخزن تنظیم کنید:

```powershell
git config user.name "Your Name"
git config user.email "you@example.com"
```

## ۵. اولین اجرا؛ بدون اتومیشن

```powershell
ai-orchestrator run --mode codex --task "خطای اعتبارسنجی فرم ورود را اصلاح کن و برای آن تست اضافه کن"
```

یا از هر پوشه، مسیر پروژه را صریح بدهید:

```powershell
ai-orchestrator run --repo "C:\Projects\MyApp" --mode cursor --task "فاصله‌های صفحهٔ ورود را اصلاح کن"
```

در حالت معمول، برنامه یک **worktree** می‌سازد: یک پوشهٔ کاری جدا متصل به همان مخزن Git. ابزار در آن پوشه کار می‌کند. فایل‌های پوشهٔ اصلی خودبه‌خود عوض نمی‌شوند. پایان اجرا مسیر خروجی و نام branch، یعنی شاخهٔ تغییرات، چاپ می‌شود.

| گزینه | معنی |
| --- | --- |
| `--mode codex` | اجرا با Codex |
| `--mode cursor` | اجرا با Cursor Agent |
| `--mode gemini` | تحلیل با Antigravity، با قرارداد فقط‌خواندنی |
| `--mode team` | برنامه‌ریزی Cursor، پیاده‌سازی Codex، تست مستقل و بازبینی Gemini |
| `--mode auto` | انتخاب ابزار با قواعد پروژه؛ ممکن است ابزار نصب‌نشده انتخاب شود |
| `--model auto` | انتخاب خودکار مدل؛ مقدار صریح آن بر تنظیم قدیمی اولویت دارد |
| `--commit-on-pass` | ثبت محلی تغییرات پس از موفقیت؛ ارسال به GitHub انجام نمی‌دهد |
| `--in-place` | کار مستقیم در پوشهٔ اصلی؛ برای شروع پیشنهاد نمی‌شود |

برای متن چندخطی یا متن دارای کوتیشن، یک فایل UTF-8 به نام `task.txt` **خارج از مخزن هدف** بسازید، درخواست را در آن بنویسید و اجرا کنید:

```powershell
ai-orchestrator run --repo "C:\Projects\MyApp" --mode codex --task-file "C:\Tasks\task.txt"
```

گزینهٔ سوم `--task-stdin` است؛ برای ابزارهایی است که ورودی استاندارد UTF-8 می‌فرستند. در هر اجرا فقط یکی از `--task`، `--task-file` یا `--task-stdin` را استفاده کنید. فایل ورودی را داخل یک مخزن تمیزِ هدف ایجاد نکنید؛ یک فایل ثبت‌نشده، اجرای ایزوله را متوقف می‌کند.

## ۶. استفاده از داخل Cursor

پروژهٔ هدف را در Cursor باز کنید. در چت Agent:

```text
/ai-codex خطای ورود را اصلاح کن و تست آن را اضافه کن
/ai-cursor چیدمان صفحه را اصلاح کن
/ai-team بخش احراز هویت را با برنامه، تست و بازبینی اصلاح کن
/ai-models
```

هر خط یک درخواست جداست. دستورهای قدیمی همچنان قابل استفاده‌اند. اگر Skillها دیده نمی‌شوند، `ai-orchestrator install-skills` را در PowerShell اجرا و پنجرهٔ Cursor را بازآوری کنید. برای کنترل دقیق بودجه یا حافظه از دستور `run` استفاده کنید.

## ۷. خروجی را کجا ببینم و چطور نگه دارم؟

```powershell
ai-orchestrator runs list
ai-orchestrator runs show RUN_ID
ai-orchestrator runs events RUN_ID
```

به‌جای `RUN_ID` شناسهٔ چاپ‌شده در فهرست را بگذارید. `result.json` نتیجهٔ قابل‌خواندن توسط برنامه‌هاست و `events.jsonl` اتفاق‌های اجرا را خط‌به‌خط ثبت می‌کند.

`PASS` یعنی آن بررسی موفق بوده؛ `FAIL` یعنی شکست خورده؛ `SKIP` یعنی اجرا نشده؛ `UNKNOWN` یعنی شاهد کافی نداریم. `SKIP` معادل موفقیت تست نیست. در کار محلیِ بدون تست، اجرا ممکن است کامل شود ولی نتیجه همچنان `tests: SKIP` دارد. اتومیشن با `tests.required: true` چنین نتیجه‌ای را قبول نمی‌کند.

اگر بدون `--commit-on-pass` فایل تغییر کرده باشد، worktree حفظ می‌شود. مسیر `worktree` را از نتیجه بردارید:

```powershell
cd "WORKTREE_PATH"
git status
git diff
```

فایل‌های جدید را نیز باز کنید؛ `git diff` به‌تنهایی محتوای فایل ثبت‌نشده را نشان نمی‌دهد. پس از بررسی، فقط فایل‌هایی را که می‌خواهید ثبت کنید با `git add` اضافه کنید و commit بزنید. می‌توانید بعداً commit آن شاخه را در پروژهٔ اصلی بازبینی و ادغام کنید. این مرحله خودکار نیست.

## ۸. زمان و حجم کار را محدود کنید

```powershell
ai-orchestrator run --mode codex --max-seconds 900 --max-processes 4 --task "این باگ کوچک را اصلاح کن"
```

این مثال برای عملیات worker و تست حداکثر ۱۵ دقیقه و ۴ اجرای برنامه در نظر می‌گیرد. تکرارهای retry نیز شمرده می‌شوند. دستورهای Git و آماده‌سازی کوتاه ممکن است به زمان کل اضافه شوند. تعداد فرمان‌هایی که خود مدل داخل یک جلسه اجرا می‌کند با این شمارنده اندازه‌گیری نمی‌شود.

پیش‌فرض‌ها ۳۶۰۰ ثانیه و ۲۰ اجرای برنامه‌اند. در TEAM، `--max-fix-rounds 2` سقف دورهای اصلاح داخلی را مشخص می‌کند. این سقف‌ها **سقف دلاری نیستند**؛ اگر CLI هزینه را گزارش نکند، `costUsd` مقدار `null` دارد. برای بودجهٔ مالی از امکانات حساب ارائه‌دهنده استفاده کنید.

## ۹. حافظهٔ اختیاری پروژه

```powershell
ai-orchestrator memory add --text "برای تست ورود از npm test استفاده کن"
ai-orchestrator memory list
ai-orchestrator memory search --text "تست ورود"
ai-orchestrator run --mode codex --memory --task "تست ورود را اصلاح کن"
ai-orchestrator memory remove NOTE_ID
```

این دستورها را از پوشهٔ پروژه اجرا کنید یا `--repo` بدهید. یادداشت‌ها فقط برای همان پروژه‌اند و پیش‌فرض پس از ۹۰ روز در بازیابی استفاده نمی‌شوند؛ با `--days 30` زمان دیگری تعیین کنید. انقضا فایل را پاک نمی‌کند؛ `remove` آن را پاک می‌کند. بدون `--memory` هیچ یادداشتی به مدل فرستاده نمی‌شود. حافظه به‌صورت خودکار از پاسخ مدل پر نمی‌شود.

## ۱۰. صف محلی؛ زمان اجرا دست خودتان

```powershell
ai-orchestrator queue add --mode codex --task "تست اعتبارسنجی را اضافه کن"
ai-orchestrator queue list
ai-orchestrator queue run --limit 1
ai-orchestrator queue cancel JOB_ID
```

`add` فقط درخواست را ذخیره می‌کند؛ مدل را اجرا نمی‌کند. `run` صف را در همان پنجره و به‌ترتیب اجرا می‌کند. بستن پنجره ممکن است اجرا را قطع کند. متن فایل ورودی هنگام افزودن کپی می‌شود؛ تنظیمات عمومی هنگام اجرا خوانده می‌شوند. هر کار worktree جدا دارد و خروجی یک کار خودکار وارد کار بعدی نمی‌شود؛ برای کارهای وابسته ابتدا نتیجهٔ قبلی را بررسی و در شاخهٔ هدف ادغام کنید.

اگر اجرا قطع شد، صف آن کار را خودکار دوباره اجرا نمی‌کند. نتیجه و فایل‌هایش را بررسی کنید. اگر قفل باقی مانده، بخش بازیابی [راهنمای فنی](LOCAL-MODULES.md#crash-recovery) را بخوانید؛ سپس `queue recover JOB_ID` آن را `INTERRUPTED` علامت می‌زند. این دستور ادامهٔ جلسهٔ مدل نیست.

## ۱۱. مسیر‌دهی با کمک دادهٔ واقعی

```powershell
ai-orchestrator routing stats
ai-orchestrator routing recommend --text "باگ اعتبارسنجی را اصلاح کن"
ai-orchestrator run --mode auto --routing learned --task "باگ اعتبارسنجی را اصلاح کن"
```

این نسخه آمار محلی را مقایسه می‌کند؛ آموزش شبکهٔ عصبی انجام نمی‌دهد. برای یک ابزار/مدل باید حداقل ۵ نتیجهٔ تست‌شده در همین پروژه و دستهٔ کار موجود باشد و دست‌کم ۸۰٪ موفق باشند. در نبود دادهٔ کافی قواعد قبلی استفاده می‌شوند. تحلیل فقط‌خواندنی و کارهای پرریسک TEAM با این روش به یک مسیر ویرایش ساده تبدیل نمی‌شوند. انتخاب دستی ابزار یا مدل اولویت دارد.

## ۱۲. اتومیشن GitHub کاملاً جداست

اگر آن را نمی‌خواهید، فایل زیر را در حالت خاموش نگه دارید و فقط روش‌های بالا را استفاده کنید:

```yaml
automation:
  enabled: false
  mode: manual
```

این تنظیم در `.github/ai-orchestrator.yml` مخزن هدف است. `mode` در این فایل دربارهٔ اتومیشن است؛ `--mode codex` در دستور محلی دربارهٔ انتخاب ابزار است.

برای اتومیشن، ابتدا [راهنمای GitHub](AUTOMATION.md) و [آزمایش اولیه](GITHUB-LIVE-TEST.md) را انجام دهید: احراز هویت GitHub، runner ویندوز اختصاصی، پیکربندی مخزن و workflow لازم است. سپس از پوشهٔ **همان مخزن**:

```powershell
ai-orchestrator github doctor --repo OWNER/REPO
ai-orchestrator github issue inspect --repo OWNER/REPO --issue 42
ai-orchestrator github issue run --repo OWNER/REPO --issue 42 --dry-run
```

`OWNER/REPO` نام GitHub است، نه مسیر پوشه. پس از بررسی dry-run و افزودن برچسب `ai-auto` توسط فرد مجاز، حذف `--dry-run` اجرای واقعی را آغاز می‌کند و می‌تواند branch را ارسال و PR بسازد. اگر بازبینی الزامی است، مسیر TEAM را انتخاب کنید؛ مسیر تنها Codex بازبینی Gemini تولید نمی‌کند. پایان موفق `READY_FOR_HUMAN_MERGE` است؛ merge و انتشار همچنان کار انسان‌اند.

## مشکلات رایج

| پیام | کار بعدی |
| --- | --- |
| `ai-orchestrator` شناخته نشد | PowerShell را دوباره باز کنید؛ نصب‌کننده را دوباره اجرا کنید |
| `source repository has uncommitted changes` | با `git status` تغییرهای خودتان را بررسی و نگه‌داری کنید |
| مدل یافت نشد | `models refresh`؛ سپس یک مدل موجود یا `--model auto` انتخاب کنید |
| تست اجرا نشد / `SKIP` | دستور تست پروژه را تنظیم کنید؛ [جزئیات](LOCAL-MODULES.md) |
| `Local origin does not match` | برای GitHub از checkout همان مخزن اجرا کنید |
| `Lock held` | اجرای دیگری فعال است یا اجرای قبلی قطع شده؛ قفل را هنگام فعالیت پاک نکنید |
| `budget exhausted` | خروجی حفظ شده؛ ابتدا آن را بررسی، سپس بودجهٔ مناسب برای اجرای بعدی تعیین کنید |
